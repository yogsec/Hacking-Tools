## Wireless Attacks

- 📡 **[Aircrack-ng](https://www.aircrack-ng.org/)** - Complete suite for auditing Wi-Fi security, covering monitoring, attacking, testing, and cracking WEP and WPA/WPA2-PSK keys.
- 🌐 **[Kismet](https://www.kismetwireless.net/)** - Wireless network detector, sniffer, and intrusion detection system that passively collects packets and detects hidden networks.
- 🐍 **[Wifite2](https://github.com/derv82/wifite2)** - Automated wireless auditor that simplifies the process of attacking WEP, WPA, and WPS networks with minimal user interaction.
- 🔨 **[Reaver](https://github.com/t6x/reaver-wps-fork-t6x)** - Implements a brute-force attack against Wi-Fi Protected Setup (WPS) registrar PINs to recover WPA/WPA2 passphrases.
- 🧚 **[Pixiewps](https://github.com/wiire-a/pixiewps)** - Offline WPS PIN brute-force utility exploiting low entropy in vulnerable implementations via the Pixie Dust attack.
- 🖥️ **[Fern WiFi Cracker](https://github.com/matosdiego/fern-wifi-cracker)** - Python/Qt-based GUI for wireless security auditing and attack, capable of cracking WEP/WPA/WPS keys.
- 🛡️ **[Bettercap](https://www.bettercap.org/)** - All-in-one framework for Wi-Fi, BLE, HID, and Ethernet reconnaissance and MITM attacks, including PMKID association and handshake capture.
- 💥 **[hcxdumptool](https://github.com/ZerBea/hcxdumptool)** - Small tool for capturing packets from WLAN devices, specifically designed for PMKID and handshake collection for Hashcat.
- 🔓 **[hcxtools](https://github.com/ZerBea/hcxtools)** - Converts packet captures into hash files for cracking with Hashcat or John the Ripper, essential for modern WPA/WPA2 auditing.
- 🎭 **[EAPHammer](https://github.com/s0lst1c3/eaphammer)** - Targeted evil twin attacks against WPA2-Enterprise networks, supporting hostile portal and credential capture.
- 🌊 **[Fluxion](https://github.com/FluxionNetwork/fluxion)** - Social-engineering focused Wi-Fi attack tool that creates rogue access points and captive portals to harvest credentials.
- 🎇 **[Airgeddon](https://github.com/v1s1t0r1sh3r3/airgeddon)** - Multi-use bash script for Linux systems to audit wireless networks, with a comprehensive menu-driven interface.
- 💀 **[MDK4](https://github.com/aircrack-ng/mdk4)** - Wi-Fi testing tool designed to exploit common protocol weaknesses, including deauthentication and beacon flooding.
- 📶 **[Wifiphisher](https://github.com/wifiphisher/wifiphisher)** - Rogue access point framework for automated Wi-Fi phishing attacks, capturing credentials via fake captive portals.
- 🦈 **[Wireshark](https://www.wireshark.org/)** - Network protocol analyzer that can be used to inspect 802.11 frames and understand wireless traffic during assessments.
- 📻 **[HackRF One](https://greatscottgadgets.com/hackrf/)** - Open-source Software Defined Radio (SDR) platform for wireless experimentation, including capturing and transmitting signals across a wide frequency range.
- 🔵 **[BlueZ](http://www.bluez.org/)** - Official Linux Bluetooth protocol stack, providing the core tools for Bluetooth device discovery and testing.

## Telecom & 5G Security

- 📡 **[FuzzyDoo](https://github.com/gabrielepongelli/FuzzyDoo)** - Open-source framework for finding flaws in the 5G landscape, enabling dynamic test message generation for encrypted communications and supporting extensible protocol integration for 5G core networks.
- 🛡️ **[SigPloit](https://github.com/SigPloiter/SigPloit)** - Telecom signaling exploitation framework covering SS7, GTP, Diameter, and SIP protocols for testing mobile operator interconnects.
- 🔨 **[Rodan](https://github.com/Etisalat-Egypt/Rodan)** - Telecom signaling exploitation framework by Etisalat Egypt Research Labs with SS7 and Diameter support, featuring location tracking, call/SMS interception, and fraud testing capabilities.

## Supply Chain Security

- 📦 **[SLSA (Supply-chain Levels for Software Artifacts)](https://slsa.dev/)** - A security framework led by the Open Source Security Foundation (OpenSSF) that provides a checklist of standards and controls to prevent tampering, improve integrity, and secure packages across the software supply chain. SLSA v1.2, approved in November 2025, introduced a complete Source Track alongside the existing Build Track, with levels ranging from Build L1 (provenance exists) to Build L3 (hardened build platform) and Source L1 (stable revision identifier) to Source L3 (continuous enforcement of technical controls).
- 🔐 **[Sigstore](https://www.sigstore.dev/)** - An open-source project for improving software supply chain security that empowers developers to securely sign and verify software artifacts using ephemeral keys, eliminating the need for long-lived key management. Sigstore combines **Cosign** (signing client), **Fulcio** (certificate authority bound to OIDC identities), and **Rekor** (tamper-resistant transparency log) to provide identity-based signing and public auditability for release files, container images, binaries, and SBOMs.
- 🔗 **[in-toto](https://in-toto.io/)** - A CNCF-graduated framework developed at NYU Tandon that protects the integrity of the software supply chain by verifying each task in the chain is carried out as planned, by authorized personnel only, and that the product is not tampered with in transit. in-toto uses signed layouts and link metadata to create a verifiable record of the entire software development lifecycle, and its Attestation Framework v1 (2025) introduced bundle layers, Resource Descriptors, and Protobuf definitions for language-independent attestation handling.
- 📄 **[CycloneDX](https://cyclonedx.org/)** - An OWASP-led Software Bill of Materials (SBOM) standard that is lightweight and well-suited for expressing component relationships and vulnerability data. CycloneDX is the recommended choice for security-response-focused supply chain programs, with mature tooling ecosystem support and integration into vulnerability scanners and policy engines.
- 📋 **[SPDX](https://spdx.dev/)** - A Linux Foundation-maintained SBOM standard that emphasizes license compliance expression, making it popular in regulatory and compliance-focused scenarios. Both SPDX and CycloneDX support JSON and XML formats, and organizations can produce both in parallel depending on their primary focus.
- ⚙️ **[Ampel](https://github.com/carabiner-dev/ampel)** - A lightweight supply chain policy engine designed to be embedded across the software development lifecycle, verifying unforgeable metadata captured in signed attestations. Ampel works with in-toto attestations and Sigstore bundles, supports SLSA provenance and SBOM gating, and allows policies to be written as code in CEL (Common Expression Language) for checks like "Was this artifact built by my GitHub account?" or "Does my vulnerability report contain HIGH CVEs?".
- 🏗️ **[Chainloop](https://chainloop.dev/)** - An open-source evidence store for software supply chain attestations, SBOMs, VEX, SARIF, and QA reports. Chainloop provides a SLSA Level 3 compliant single source of truth built on open standards (Sigstore, in-toto, SLSA, OCI), with declarative Workflow Contracts that let Security teams define what evidence developers must provide, while shielding developers from the underlying complexity through simple CI/CD integration.
- 🛡️ **[OpenSSF Scorecard](https://scorecard.dev/)** - An automated tool from the Open Source Security Foundation that assesses repositories against a set of security heuristics and assigns each check a score from 0 to 10. Scorecard evaluates Branch-Protection, Code-Review, Dangerous-Workflow, Token-Permissions, Pinned-Dependencies, Vulnerabilities, Signed-Releases, and other signals to provide an objective read on how safely a project is maintained before adopting it as a dependency.
- 🧪 **[Macaron](https://github.com/chainreactors/macaron)** - An open-source framework presented at IEEE that enhances software supply chain security by detecting malicious code and providing comprehensive insights into the construction and provenance of software artifacts. Macaron leverages static analysis to extract metadata from open-source packages, enables build reconstruction, identifies suspicious upstream components, and enforces compliance with the SLSA framework, with capabilities for detecting Python malware in open-source ecosystems.
- 🔍 **[GardWatch](https://pypi.org/project/gardwatch/)** - A CLI tool that analyzes dependencies for trust, security risks, and quality signals across PyPI, npm, Go, Cargo, Maven, and NuGet. GardWatch uses a composite trust scoring engine (0-100) that factors in malware detection, package age and maturity, download popularity, OpenSSF Scorecard integration, metadata quality, and threat detection for typosquatting and homoglyph attacks.
- 🧩 **[Chainmail](https://chainmail.saisravancherukuri.com)** - A unified open-source workbench for software supply chain security that brings eight capabilities together in one place. Chainmail introduces a Multi-Dimensional Supply Chain Risk Score (SCRS), a graph-theoretic License Conflict Propagation (LCP) framework, and Automated VEX Generation using PURL-based version-range intersection, producing CSAF 2.0-compliant statements in under two seconds.
- 📊 **[OWASP Dependency-Check](https://github.com/jeremylong/DependencyCheck)** - A Software Composition Analysis (SCA) tool that identifies project dependencies and checks for known, publicly disclosed vulnerabilities, widely used in CI/CD pipelines for supply chain risk detection.
- 📜 **[GitLeaks](https://github.com/gitleaks/gitleaks)** - Detects hardcoded secrets, API keys, and sensitive data in Git repositories, helping prevent credential leakage in the software supply chain.
- 🧮 **[Trivy](https://github.com/aquasecurity/trivy)** - Comprehensive vulnerability scanner for containers, filesystems, Git repositories, and dependencies, with SBOM generation and scanning capabilities for supply chain visibility.
- 🔬 **[Grype](https://github.com/anchore/grype)** - An SBOM-first vulnerability scanner for container images and filesystems from Anchore, featuring threat prioritization with EPSS scores and CISA KEV indicators for supply chain risk assessment.
- 📦 **[Syft](https://github.com/anchore/syft)** - A CLI tool and library for generating Software Bills of Materials (SBOMs) from container images and filesystems, supporting CycloneDX and SPDX formats.

## Intrusion Detection & Prevention

- 🛡️ **[Snort](https://www.snort.org/)** - The world's most widely deployed open-source IDS/IPS, combining signature, protocol, and anomaly-based inspection. Snort 3 introduces a Lua-based configuration language, modular detection engine, and enhanced protocol inspection including IPv6, HTTP/2, and TLS 1.3. Achieves the highest throughput in academic benchmarks (987,966 PPS for ICMP) and the highest detection precision (0.91) in comparative studies, though Talos rules for full coverage are paid ($1,500-$12,000/year).
- ⚡ **[Suricata](https://suricata.io/)** - High-performance Network IDS, IPS, and NSM engine owned by the Open Information Security Foundation (OISF). Natively multithreaded for 10+ Gbps networks, with free ET Open ruleset (125,000+ rules, 15-minute updates), native JSON/EVE output for easy SIEM integration, OT/ICS protocol support (Modbus, DNP3), and conditional PCAP for forensic analysis. Suricata consistently outperformed Snort in scalability, resource efficiency, and detection accuracy in SME-focused studies, though its precision is slightly lower (0.86 vs. 0.91) and RAM requirements are higher.
- 🔍 **[Zeek](https://zeek.org/)** - Powerful network analysis framework that produces high-fidelity transaction logs rather than traditional alerts, serving as the evidence standard for network security monitoring. Unlike signature-based IDS, Zeek focuses on behavioral analysis and protocol parsing, making it ideal for threat hunting and forensic investigations alongside Snort or Suricata.
- 🏠 **[OSSEC](https://www.ossec.net/)** - Open-source host-based intrusion detection system (HIDS) performing log analysis, file integrity checking, rootkit detection, and active response across Linux, Windows, macOS, and Solaris. A central manager collects data from agents and runs them through ~1,500 rules to detect brute-force attempts, privilege escalation, and malware persistence, with active response capabilities including firewall blocking and account lockout.
- 🏠 **[Samhain](https://launchpad.net/ubuntu/stonking/+source/samhain)** - Open-source multiplatform HIDS providing file integrity checking, log file monitoring and analysis, rootkit detection, port monitoring, detection of rogue SUID executables, and hidden process detection. - 🧠 **[Splunk](https://www.splunk.com/)** - AI-driven anomaly detection and IPS traffic analyzer with automated intrusion remediation capabilities. ## Cryptography & Encryption

- 🔐 **[age](https://github.com/FiloSottile/age)** - A simple, modern and secure file encryption tool, format, and Go library with small explicit keys, no config options, and UNIX-style composability. Supports X25519 recipients, SSH keys, passphrase encryption with auto-generated secure passphrases, and hybrid post-quantum keys via the `-pq` flag for protection against future quantum computer attacks.
- 🏗️ **[OpenXPKI](https://www.openxpki.org/)** - Enterprise-grade open-source PKI/trustcenter solution written in Perl, supporting CA rollover, multiple PKI realms in a single installation, hardware security modules (nCipher nShield, SafeNet Luna), threshold secret sharing, database backends including Oracle, SCEP for embedded device certificate enrollment, REST/SOAP interfaces, and a workflow engine for custom PKI processes.
- 🛡️ **[Dogtag Certificate System](https://www.dogtagpki.org/)** - Robust, scalable enterprise PKI solution managing the complete digital certificate lifecycle including creation, storage, distribution, and revocation. Features extreme flexibility in certificate profiles, workflows, and policies, with HSM integration via PKCS #11, multi-factor authentication, detailed audit logging, X.509/LDAP/PKCS #11 standards compliance, and multi-platform support.
- 🧰 **[Step CLI](https://smallstep.com/cli/)** - Easy-to-use CLI tool for building, operating, and automating PKI systems. Provides `step certificate` for X.509 operations including creation, revocation, validation, linting, and trust store installation; `step ca` for ACMEv2-compliant CA administration; `step crypto` for JWTs, JWS, JWE, TOTP, NaCl, and KDFs (scrypt, bcrypt, argon2); and `step ssh` for SSH certificate management. Integrates with HSM/TPM/YubiKey through the step-kms-plugin.
- 🔒 **[GnuPG (GPG)](https://gnupg.org/)** - Complete OpenPGP implementation for digital encryption and signing services. GnuPG 2.x supports modern encryption algorithms including Kyber keys implemented as composite ECC keys (PQ/T hybrid) for post-quantum resistance. Features complete key management including export, import, list-keys with fingerprints, delete-key, export-secret-subkeys (with the option to render primary key useless), and `--export-ssh-key` for OpenSSH format conversion. Common operations include `gpg -se -r Bob file` for sign-and-encrypt, `gpg --clear-sign file` for cleartext signatures, and `gpg --verify sigfile` for detached signature verification.
- 🔓 **[OpenSSL](https://www.openssl.org/)** - The de facto standard cryptographic toolkit providing a comprehensive command-line interface for symmetric ciphers (AES-128/192/256, ARIA, Blowfish, Camellia, CAST5, ChaCha20, DES/3DES, IDEA, RC2/4/5, SEED, SM4), message digest commands (BLAKE2, MD5, SHA-1, SHA-2, SHA-3, SHAKE, SM3), X.509 certificate verification and management, and Base64 encoding. Supports multiple cipher modes including CBC, CFB, CTR, ECB, and OFB for each algorithm.
- 💿 **[Tomb](https://www.tomb.dyne.org/)** - Free and easy-to-operate desktop application for strong encryption of personal files using dm-crypt/cryptsetup with the aes-xts-plain64 cipher. Operates as a "locked folder" that can be transported and hidden in filesystems, requiring both a keyfile and a password to open. Keys can be kept separate (tomb on harddisk, key on USB stick), with steganography support for hiding keys inside JPEG/WAV files, bind hooks for automatic directory mounting, and post hooks for running commands on open/close.
- 🎨 **[GTKCrypto](https://github.com/paolostivanin/GTKCrypto)** - GTK+ application for encrypting and signing files or text, supporting AES, Twofish, Serpent, and Camellia cipher algorithms with 256-bit keys in CBC or CTR mode. Also computes and compares MD5, SHA-1, SHA-2, SHA-3, GOST, and Whirlpool hashes for file integrity verification.
- 🔬 **[Quinto](https://pypi.org/project/quinto/)** - CLI tool that automates hash cracking by identifying hash types using prefix matching, name-that-hash, and hashid, then orchestrating hashcat and John the Ripper through a sequence of attacks: wordlist → wordlist + rules → masks → EFF diceware passphrases. Handles password-protected files (.zip, .pdf, Office docs) by extracting hashes with John's `*2john` tools first, with session state saving for resume capability.
- 🧪 **[Hashcat](https://hashcat.net/)** - Advanced password recovery tool and the world's fastest CPU-based password cracker, supporting over 300 hash types including MD5 (`-m 0`), SHA-1 (`-m 100`), and SHA-256 (`-m 1400`). GPU-accelerated for massive throughput, widely used in CTF competitions and authorized penetration testing for credential recovery.
- 🔨 **[John the Ripper](https://www.openwall.com/john/)** - Open-source password security auditing and recovery tool, handling hash formats that hashcat doesn't support and extracting hashes from protected files via `*2john` utilities. Includes `gpg2john` for converting GPG files to crackable format, with CPU performance tested at 1,120-1,508 MH/s for MD5 depending on configuration.
- 🧅 **[CyberChef](https://gchq.github.io/CyberChef/)** - The "Cyber Swiss Army Knife" web application from GCHQ for encryption, encoding, compression, and data analysis. Provides a drag-and-drop interface for chaining operations including Base64, AES, RSA, hashing, and classical ciphers, with 36,000+ GitHub stars.
- 📚 **[Cryptii](https://cryptii.com/)** - Web-based modular conversion, encoding, and encryption tool supporting classical ciphers (Caesar, Vigenère, substitution, transposition), modern ciphers (AES, RSA), and various encoding schemes.

## Compliance & Auditing

- 🛡️ **[OpenSCAP](https://www.open-scap.org/)** - The reference implementation of the SCAP (Security Content Automation Protocol) standard, NIST-certified and built into RHEL and derivatives. Evaluates OVAL vulnerability definitions and XCCDF benchmark profiles including CIS, PCI-DSS, STIG, and USGCB, with HTML and XML report generation. Supports remote scanning via `oscap-ssh` without installing agents, and optional auto-remediation through the `--remediate` flag. In FABRIC testbed experiments, OpenSCAP compliance rates improved from 39.73% to 71.82% after hardening.

- 🔍 **[Lynis](https://cisofy.com/lynis/)** - Open-source security auditing and hardening tool for Linux and Unix systems with 200+ individual tests and a hardening index score (0-100). Excels at quick, repeatable configuration audits covering kernel, services, authentication, and filesystem checks, validating both CIS, NIST, and NSA hardening specifications. In FABRIC experiments, Lynis baseline scores of 63.08 improved to 64.92 post-hardening, with runtime efficiency making it ideal for rapid iterative audits.

- 🏢 **[CIS-CAT Pro](https://www.cisecurity.org/cybersecurity-tools/cis-cat-pro/)** - Official CIS Benchmark assessment tool providing automated verification across 80+ benchmarks covering nearly all operating systems. Proprietary Java-based cross-platform application requiring Java Runtime Environment (JRE 6, 7, or 8), generating pass/fail/error/unknown/not-checked scores with detailed scan reports. Integrated into Wazuh agents via the CIS-CAT wodle module, enabling scheduled compliance scans with configurable intervals, timeout settings, and profile selection.

- 📊 **[Wazuh SCA (Security Configuration Assessment)](https://wazuh.com/)** - Built-in compliance assessment module within the Wazuh SIEM platform, performing policy monitoring and configuration checks against CIS Benchmarks and custom security policies. CIS-CAT integration extends Wazuh agents with full CIS Benchmark assessment capabilities, sending scan results as alerts to the Wazuh manager for correlation and visualization. Enables continuous compliance monitoring with daily automated scans and fleet-wide visibility across heterogeneous environments.

- 🎯 **[Chef InSpec](https://inspec.io/)** - Open-source testing framework for infrastructure compliance, with the `auditd` resource for testing audit rules against system configurations. Integrated into Chef Automate for centralized compliance reporting, with the `opsworks-audit` cookbook orchestrating DevSec SSH Baseline profile scans. Supports custom compliance profiles, automated remediation, and deployment pipeline integration, with InSpec gem version 1.24.0+ required for Chef Automate 1.x compatibility.

- 📜 **[OpenSCAP Workbench](https://www.open-scap.org/tools/openscap-workbench/)** - GUI for OpenSCAP that allows browsing XCCDF profiles, running scans, and generating reports without command-line interaction. Simplifies compliance assessment for administrators who prefer visual workflows while maintaining the same SCAP-compliant engine as the `oscap` CLI.

- 🐧 **[Ubuntu Security Guide (USG)](https://documentation.ubuntu.com/security/compliance/usg/)** - Canonical's built-in compliance tooling for Ubuntu systems, providing CIS Benchmark profiles at Level 1 and Level 2 for both workstation and server configurations. Audits systems using `sudo usg audit cis_level1_server` with HTML and XML report generation at `/var/lib/usg/`, and supports profile customization to remove unnecessary rules or tailor options to specific environments.

- 🔧 **[AIDE (Advanced Intrusion Detection Environment)](https://aide.github.io/)** - File integrity monitoring tool that creates cryptographic checksums of system files and detects unauthorized modifications, complementing compliance scanning by verifying that hardened configurations remain unchanged. Used alongside Lynis and OpenSCAP in multi-tool compliance aggregation frameworks to provide comprehensive coverage across configuration auditing, compliance validation, and integrity monitoring.

- 📈 **[FABRIC Unified Compliance Aggregator (UCA)](https://arxiv.org/abs/2601.00909)** - Academic framework that normalizes heterogeneous compliance outputs from Lynis, OpenSCAP, and AIDE into a unified scoring system using weighted metrics (0.4 for Lynis, 0.4 for OpenSCAP, 0.2 for AIDE). Demonstrates that aggregating complementary tools yields clearer, more interpretable security assessments than analyzing individual tools in isolation, validated across 108 audits on Ubuntu nodes at varying hardening levels.

- 🚀 **[cis-host](https://pypi.org/project/ohbs-host/)** - PyPI-distributed CIS Benchmark scanner and remediator with per-host HTML reports featuring traffic-light scoring (green ≥ 90, amber ≥ 70, red otherwise) and a weighted Hardening Index that prioritizes high-risk rule failures. Supports fleet scanning with aggregate dashboards, drift detection comparing scan results over time, and CI-friendly audit mode that exits non-zero when compliance thresholds are not met.

- 🧪 **[Hardenix](https://github.com/murat-akpinar/hardenix)** - OpenSCAP-powered Linux hardening CLI that combines compliance scanning with Lynis second-opinion audits and OVAL-based CVE detection in a single workflow. Features a dead-man switch for safe remote hardening (`--deadman 10` auto-reverts unless confirmed), dry-run preview, and YAML-based profiles with distro-specific configuration . CI gate mode uses `--min-score 90` to block deployments when compliance falls below threshold.

- 📋 **[Pavois](https://github.com/stephrobert/pavois)** - Effective Linux compliance and hardening tool over CINC/InSpec producing A-E grades with multi-standard mappings including CIS, ANSSI BP-028, NIST, PCI-DSS, and STIG. Generates tamper-evident evidence bundles with SLSA build provenance and OpenSSF Scorecard verification, supporting `cosign sign-blob` or `gpg --detach-sign` for auditor-opposable attestation. The `diff` command produces campaign reports with transition matrices showing failed→passed transitions, regressions, and grade deltas for audit evidence.

## Penetration Testing Distributions

- **Kali Linux** - Developed by Offensive Security, Kali remains the dominant penetration testing distribution with 600+ pre-installed tools organized into metapackages covering vulnerability assessment, web testing, wireless security, exploitation, forensics, and reporting. The 2026.2 release ships with kernel 6.19, GNOME 50, KDE Plasma 6.6, and adds nine new tools including arsenal-ng (200+ cybersecurity cheat-sheets), legba (multiprotocol credential bruteforcer), oletools (MS OLE2/Office document analysis), shell-gpt (AI-powered CLI), and tookie-osint (social media OSINT). Kali is the only distribution officially aligned with OffSec's PEN-200 curriculum and OSCP exam environment, making it the default choice for certification preparation. Pre-built VM images for VirtualBox and VMware now exclude graphics firmware for VM users, cutting initrd to 60 MB and reducing boot time by approximately 3x.
- **Parrot OS** - A Debian-based distribution offering 800+ tools in its Security Edition, with a notably lighter footprint than Kali (320 MB minimum RAM vs. 1 GB). The 7.4 release introduces optimized ISO images targeting modern CPU architectures (amd64v3 using AVX2/FMA/BMI2, arm64v8.2 with LSE atomics and crypto extensions) for faster operations and longer battery life on post-2015 hardware. Parrot includes AnonSurf (Tor traffic routing) and hardened kernel out of the box, positioning it as suitable for both penetration testing and privacy-conscious daily use. The project provides multiple editions: Security Edition for pentesting and forensics, Home Edition for daily use, HTB Edition for Hack The Box challenges, and Raspberry Pi/ARM images.
- **BlackArch Linux** - An Arch Linux-based distribution containing the largest tool repository of any security distro, with 2,200+ tools as of the 2026.06.01 release. BlackArch is not a standalone distribution in the traditional sense but a set of repositories that can be installed alongside an existing Arch system, giving experienced users modular control over their environment. It supports x86_64, armv6h, armv7h, and aarch64 architectures, with multiple window managers including dwm, fluxbox, openbox, awesome, i3, and spectrwm. The trade-off is higher maintenance overhead: Arch's rolling-release model means dependency conflicts require manual resolution, and there is no hand-holding for beginners.
- **Kali NetHunter** - Kali's mobile penetration testing platform for Android devices, supporting Wi-Fi injection, HID keyboard attacks, and EvilTwin Wi-Fi fake access point scenarios. The 2026.2 release adds Magisk standalone kernel flashing support, instant app launching, and a new EvilTwin tab with password verification captive portal.
- **Kali Purple** - A defensive security variant of Kali that integrates SOC tooling, threat hunting capabilities, and detection engineering into the familiar Kali environment, bridging offensive and defensive operations.
- **Commando VM** - Mandiant's Windows-based security distribution for penetration testers, providing a curated set of offensive tools in a Windows environment for red team engagements requiring native Windows tooling.
